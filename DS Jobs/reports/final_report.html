Talent Analytics · Data-Source Review · Tier A

This Glassdoor dataset cannot benchmark pay — but it can map the data-science role market

A forensic review of the most widely used public DS-jobs dataset, for the compensation-review and job-architecture cycle.

Situation Talent teams need external salary benchmarks and role-spec guidance, and this 672-posting Glassdoor scrape is the most widely used public dataset for exactly that — its canonical use is a salary-prediction model, reproduced in hundreds of public notebooks.

Complication The salary field does not behave like a measurement. 26 distinct values cover 672 rows in 30 perfectly contiguous index blocks; 98.7% of repeated postings carry two or more different bands, up to $179K apart; and seniority carries a $1.1K discount.

Resolution Salary Estimate is a search-query artifact — the scrape batch label, not the job's pay. The comp-benchmarking use must be stopped, not caveated. The file's genuine value is a role-and-skill market map, where role family is recoverable from description text at macro-F1 0.71.

The only thing that predicts a posting's “salary” is which scrape returned it; the data that says nothing about pay says a great deal about roles and skills.
  1. The salary field is a scrape artifact. 30 salary bands fall in 30 unbroken blocks of rows (η²=1.000, permutation p<0.0001), while company rating varies freely within those same blocks (η²=0.0235) — ruling out an innocent sort.
  2. Nothing predicts it, and no model beats a constant. Every job attribute falls below its statistical detection floor; seven tuned models under honest validation top out at R²=-0.01, short of the pre-registered 0.20 bar.
  3. The role-and-skill structure is real. Tableau appears in 51% of analyst postings and 0% of ML-engineer postings; a PhD is demanded by 57% of ML-engineer postings versus 6% of analyst postings.
  4. One model ships. Role family is recoverable from description text at macro-F1 0.71 (83% accuracy) versus a 0.16 baseline — useful auto-tagging for a title field that is 50% one value.

Recommendation

Talent Analytics should (1) remove this source from the compensation-benchmarking evidence base before the next comp cycle; (2) adopt it as a role-and-skill structure reference, quoted at the posting level, never for pay; and (3) ship the role-family tagger against the 172-value title field, with class-aware thresholds and the vocabulary-drift monitor attached.

Part I · The salary field is an artifact

Thirty salary values fall in thirty unbroken blocks of rows

If salary were a property of the job, its values would scatter through the file in collection order. Instead each of the 30 distinct values occupies one contiguous run of row indices — the fingerprint of 30 separate Glassdoor searches, each with its own salary filter, concatenated in order.

So What: the file is 30 search queries stitched together; the salary column is a batch label denominated in dollars. A permutation test rejects chance at p<0.0001 — a random assignment would produce ≈650 blocks, not 30.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 672 postings / 492 unique.

The identical posting sells for wildly different pay depending only on which search returned it

So What: 149 of 151 repeated postings (98.7%) carry two or more salary bands, median disagreement $28K, maximum $179K. A quantity that takes five values for one unchanged job is not measuring that job.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 672 postings / 492 unique.

Salary is frozen within a batch while everything else varies freely — ruling out a simple sort

So What: the obvious objection is that the vendor sorted rows by pay. That would have moved every column; instead salary is constant within batch (η²=1.000) while rating (η²=0.0235, p=0.99), posting length and company age vary freely. The artifact is specific to the target.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 672 postings / 492 unique.

Part II · Nothing predicts it

No job attribute survives a powered test for a salary effect

A null result only counts when the test could have found something. Each attribute is shown with the effect its own sample size could detect at 80% power, and with the bias-corrected ε² that strips out the spurious variance many groups create by chance.

So What: the only cut that clears both its floor and FDR correction is estimate provenance — scrape metadata, not a job attribute. Every genuine attribute is null: seniority moves pay $-1.1K (d=-0.03) where d=0.29 was detectable, and rating correlates r=+0.002.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 672 postings / 492 unique.

Seven tuned models, both protocols, and not one beats predicting the mean

So What: the best honest score is R²=-0.01 — below a constant, and under a third of the way to the pre-registered 0.2 bar. The random-split bars sit beside the honest ones: the 43% duplicate leakage buys nothing, because a repeated posting carries a different label. The rejection is now the verdict of a properly built model.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 672 postings / 492 unique.

Part III · What the file does show

Skill demand separates cleanly by role — the structure salary lacks

So What: the same file that carries no salary signal carries strong role signal. Tableau runs 51%→0% across the analyst-to-ML-engineer axis; Spark runs the other way. These are large, monotone, interpretable — the raw material for a skills taxonomy and job-spec guidance.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 492 unique postings.

A PhD gates half of ML-engineer postings — an access barrier, not a skill signal

So What: a PhD is named in 57% of ML-engineer postings versus 6% of analyst postings, while median stated experience is flat across roles. That is a hiring-design and access-equity finding: the ML-engineer entry gate is a credential, with documented disparate-impact risk.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 492 unique postings.

Part IV · The model that ships

Role family is recoverable from description text at macro-F1 0.71

So What: a linear text classifier recovers role family at macro-F1 0.71 (83% accuracy) versus a 0.16 majority baseline — Data Scientist near-perfect (F1 0.89). Confusions cluster on the Data-Engineer↔ML-Engineer boundary, a real vocabulary overlap. It needs class-aware thresholds before deployment.

Source: Kaggle 'Uncleaned Data Science Jobs' (Glassdoor scrape, ~2020, US-centric). 492 unique postings.

Appendix · Methodology & limitations

Pipeline

Six notebooks: ingestion (schema + batch-structure gate) → cleaning (sentinel audit, three-level dedup) → EDA → forensic diagnostic (permutation test, effect sizes, MDE, FDR, pre-registration) → modelling (7-family salary bake-off, role tagger, rating model) → this report. Seed 42 throughout; GroupKFold on posting identity for every model. Stack: pandas, scikit-learn, statsmodels, xgboost.

Why the salary model was built at all

The project owner asked for the canonical salary-prediction deliverable in full. It was built to its best — full feature set, seven families, tuned XGBoost (tuned R²=-0.01) — precisely so the rejection could not be attributed to a weak attempt. The acceptance test was pre-registered before any model ran (reports/_preregistration.json).

The irreducible ceiling

Because identical postings carry different bands, within-replicate variance caps R² at ≈0.46 on the rows where the floor is observable — no feature set can exceed it. The report quotes 0.46, not the optimistic 0.71.

Fairness

The tagger affects access to opportunities, so a protected-subgroup audit is mandatory — and impossible: the file has no applicant or demographic attribute. That impossibility caps any deployment recommendation. Runnable audits were run: tagger error concentrates in the smallest role families (up to 51%), and credential gating is a documented access barrier.

Monitoring (specification, untested)

PSI on TF-IDF vocabulary and predicted role mix; macro-F1 on a labelled monthly sample. The expected failure mode is dated vocabulary — this ~2020 corpus contains no “LLM”, “RAG”, or “prompt engineering”, so the tagger degrades on modern postings by construction.

Limitations

Salary figures are Glassdoor estimates, never observed pay (20 rows are employer-supplied on a different basis). There is no date field, so nothing here is a trend and the ~2020 vintage is inferred. n=492 unique postings is small, so state- and sector-level cuts are directional only. The scrape is US-centric and DS-title-biased by construction. role_family is a keyword map authored here, so the tagger's ceiling is limited by label noise. No causal claim is available for any association.
